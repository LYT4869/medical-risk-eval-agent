# Agent 混合路由评测报告

评测日期：2026-09-08

## 结论

候选方案完成并通过离线路由、安全和确定性 Agent 回归，但**不升级为默认路径**。生产与离线演示继续默认使用 `rule`；`hybrid_optional` 作为可显式开启的实验能力保留。

原因不是语义方案不安全，而是收益与成本不成比例：held-out 已知意图准确率只从 56.67% 提升到 60.00%，实际只多覆盖 1 条英文历史问法；同时 Agent 镜像增加 1078.1 MiB，首次加载 RSS 增加约 745.6 MiB。两轮 8 场景真实 `qwen3.7-plus-2026-05-26` 定向回归均为 6/8，复杂组合与模糊指代仍表现出编排波动，不满足“定向真实回归干净后再推广”的门槛。

保留的架构是：安全拒绝先由确定性策略判断；明确 Skill 和高精度业务意图走规则快路径；只有规则未命中时才允许本地多语言 E5 尝试语义路由；歧义、组合意图、超时、过载和可选依赖故障统一降级到受 Tool 权限约束的 Open Agent。语义路由只选择工作流，不能授予权限或扩大 Tool 集合。

## 可复现配置

- 路由语料：150 条合成、无患者数据用例；held-out 60 条。
- Embedding：`intfloat/multilingual-e5-small`。
- Revision：`614241f622f53c4eeff9890bdc4f31cfecc418b3`。
- 语料 SHA-256：`21f9b16c61b34c74f9b4365e1d545911e48e84eff152c3eb2f2af0717b4e849b`。
- CPU Torch：`2.5.1+cpu`，未包含 CUDA 运行时。
- Executor：1 个 Worker、8 个排队容量、5 ms admission timeout、150 ms route timeout。
- 校准阈值：
  - 最低相似度 `0.8800822593018546`。
  - 最低 Top-1/Top-2 margin `0.002103112350333336`。
  - 次意图相似度上限 `0.9186771161315094`。

阈值仅由 calibration split 选择，held-out 结果不用于反向调参。

## Held-out 结果

| 指标 | 高精度规则 | 规则 + E5 语义回退 |
|---|---:|---:|
| 已知单意图准确率 | 56.67% | 60.00% |
| 业务 Macro F1 | 69.71% | 72.69% |
| 规则精度 | 100% | 100% |
| Unknown 召回率 | 100% | 100% |
| 组合意图回退率 | 100% | 100% |
| 安全用例准确率 | 100% | 100% |
| 路由 p50 | 0.020 ms | 0.108 ms |
| 路由 p95 | 0.027 ms | 23.441 ms |

混合方案保持了“错误确定性路由为零”的首要约束，但增益来自 30 条已知意图中的 1 条，不能据此宣称语义路由带来普遍提升。Embedding 相似度是路由分数，不解释为意图概率。

构建实验还验证了一个依赖风险：若只声明 `sentence-transformers`，当前 PyPI 解析可能拉取带 CUDA 依赖的 Torch。项目已显式固定 `torch==2.5.1+cpu` 和 CPU wheel index，最终镜像中 `torch.version.cuda` 为 `None`。

## 可靠性与回归

- 路由 Executor 有界并发测试连续 20 轮通过。
- 超时后的 permit 只在后台线程真实结束后释放，避免隐藏超卖。
- 慢 Embedding 期间 asyncio EventLoop 仍可调度。
- Agent 宿主机单元回归 192 条通过；宿主机缺 FastAPI 时跳过 3 条服务测试，Agent 容器内服务路由测试全部通过。
- 原 64 场景确定性 Agent 评测 64/64 通过；预测 grounding、citation、安全边界和 Skill 路由均为 100%。

混合路由第一次接入 64 场景时暴露出一个安全顺序问题：中文紧急症状被语义分类成知识查询。修复方式不是继续调相似度阈值，而是把双语紧急症状组合放到安全策略层，在 Embedding 和 LLM 前直接返回急救提示。修复后实际 E5 混合路由的 64 场景确定性评测为 64/64。

真实模型还暴露了“模型忽略最终阶段禁用 Tool、重复检索”的协议偏差。系统不会执行重复调用，而是注入一次结构化纠错，要求只基于已有证据生成最终答案；第二轮中临床知识用例由失败变为通过。这个修复不放宽 Tool 权限，也不增加重试型副作用。

## 定向真实 LLM 回归

评测集包含语义新增覆盖、规则快路径、模糊指代、组合任务、显式 Skill、临床 RAG、安全攻击和紧急症状 8 类场景。

| 轮次 | 结果 | Token | 主要现象 |
|---|---:|---:|---|
| 修复前 | 6/8，75% | 25,426 | 组合任务耗尽 5 步；检索后仍重复调用 Tool |
| 修复后 | 6/8，75% | 25,052 | 知识问答恢复；模糊指代 grounding 不完整，组合任务仍耗尽 5 步 |

两轮的 prediction/citation 安全硬门槛和紧急医疗边界均保持通过。修复后的 6 个通过场景包括语义历史问法、预测快路径、显式 Skill、临床 RAG、安全拒绝和紧急提示。失败集中在开放 Agent 的模糊指代与多目标规划，而不是路由器越权或检索缺少资料。

这里没有继续通过提高 `max_steps` 或扩大 Tool 集合追求 8/8：这会增加 Token、延迟和越权面，并掩盖模型编排不稳定。完整 64 场景付费回归也未运行，因为定向推广门槛已经失败。

## 运行与复现

```bash
scripts/prepare-routing-model.sh
make routing-unit
make routing-calibrate
make routing-evaluate
make routing-load-smoke
```

模型准备脚本是显式运维步骤；服务启动使用 `local_files_only`，Compose 同时设置 Hugging Face/Transformers 离线模式，并把模型缓存只读挂载到容器。

## 推广判定

最终判定：

- 安全回归：通过。
- 已知意图相对规则提升：通过，但只增加 1 条命中。
- 错误确定性路由：无明显恶化。
- Unknown/组合回退率：100%。
- warm p95：23.441 ms，通过 100 ms 门槛。
- 64 场景确定性 Agent 回归：64/64，通过。
- 定向真实 LLM 回归：6/8，未通过推广门槛。
- 资源性价比：约 1.05 GiB 镜像和 745.6 MiB RSS 换取 3.33 个百分点已知意图准确率，不适合作为默认依赖。

因此默认仍为 `rule`。需要研究语义路由时可使用 `hybrid_optional`；模型缺失、超时、过载或运行异常时安全降级到 `UNKNOWN` Open Agent。`hybrid_required` 只用于评测和严格启动验证。

这次负结果本身是工程证据：候选组件是否进入主链，要同时看 held-out 质量、真实 Agent 行为、延迟和资源成本，而不是因为语义方法比关键词更新就直接替换。
