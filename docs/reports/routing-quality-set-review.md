# Routing Quality Set 生成、审核与 Calibration 报告

评测日期：2026-09-09

## 结论

按照冻结的路由任务说明书生成了 396 条无患者数据候选，审核后冻结为 360 条：120 条 Calibration、240 条 Heldout。候选生成、去重、人工筛选和数据划分均在运行新语料路由评测之前完成；Heldout 尚未运行，也没有参与规则、语义阈值或候选筛选。

Calibration 暴露了旧 150 条小型合成集没有覆盖的问题：当前安全策略只能识别较窄的固定表达，组合意图规则也依赖有限连接词和业务标记。`rule` 和 `hybrid_optional` 的安全准确率都只有 15%，因此当前不能切换默认路由，也不能直接运行 Heldout 后再反向修改策略。

下一步应只使用 Calibration 完善确定性安全边界和组合意图回退；完成并冻结修改后，再对 240 条 Heldout 运行一次最终评测。

## 候选生成与数据边界

- 生成方式：当前开发助手依据已冻结说明书直接编写，没有调用千问或其他外部 API。
- 原始候选：396 条，其中 known 216、unknown 60、compositional 60、safety 60。
- 语言分布：中文 252、英文 72、中英混合 72。
- 输入仅包含虚构演示样本编号和合成请求，不包含真实患者资料。
- 生成阶段没有使用 `split`，也没有根据路由输出选择或重写消息。
- 候选生成者并非独立第三方标注团队，因此这套数据适合作为项目工程质量门槛，不应包装成外部权威基准。

## 已定位根因

当前确定性安全层采用少量短语组合：

- 安全越权主要依赖“伪造、编造、绕过”等动作与“权限、其他患者、概率”等受保护对象同时出现；
- 医疗边界主要依赖“为我、个体化”等个人化标记与“处方、剂量、诊断”等临床动作同时出现；
- 紧急情况要求出血、生命体征异常和“现在”等三组词同时命中。

新 Calibration 包含角色伪造、Capability 扩权、凭据泄露、审计规避、停药/手术决定、治疗保证及更多自然的紧急表达。这些概念没有被现有短语集合完整覆盖，因此大部分安全请求落到 Unknown，少量又被普通业务规则或语义回退误路由。

组合意图同样存在类似问题：当前规则只覆盖部分意图组合和有限连接表达，无法稳定识别更自然的顺序请求、省略组合和三任务请求。

## 下一门槛

1. 只用 120 条 Calibration 增加概念化安全规则和组合意图检测测试。
2. 安全边界继续位于规则和 Semantic Router 之前，不让 Embedding 决定权限或医疗拒答。
3. Calibration 达到安全、组合、Unknown 硬门槛后冻结代码和阈值。
4. 只运行一次 240 条 Heldout，记录 Rule 与 Hybrid 的最终结果。
5. 只有 Heldout 证明 known 收益合理且安全/回退无退化，才考虑把 `hybrid_optional` 升为默认。

当前正确结论仍是：FP32 ONNX 已证明部署等价，但 Hybrid 路由的泛化质量尚未通过推广门槛。
