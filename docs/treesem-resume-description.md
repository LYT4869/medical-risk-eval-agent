# treeSem 简历项目描述

## 推荐主版本

### treeSem 医疗智能服务｜C++ 后端 / Agent 工程

**技术栈：** C++17、Muduo、ONNX Runtime、MySQL、Python、MCP、FAISS、Docker

面向产后出血风险预测与解释场景，将研究模型工程化为集 C++ 推理、业务持久化、权限控制和
知识增强智能体于一体的医疗辅助服务。

- 基于 Kama/Muduo 二次开发 C++ HTTP 网关，采用 Reactor 和独立有界线程池隔离模型推理、
  数据库及智能体调用，实现超时控制、过载快速失败、跨线程安全回包和优雅停机。
- 设计版本化模型服务包，将确定性神经网络导出至 ONNX，并在 C++ 中完成预处理与决策树解释；
  在 1489 个样本上实现 Python/C++ 离散结果完全一致，最大概率误差 `1.79×10⁻⁷`。
- 基于 MySQL 短事务实现会话、预测快照、历史比较和幂等反馈，结合访问令牌、资源级权限校验
  和短期能力令牌，限制医生、患者及智能体的跨用户访问。
- 实现具备步骤、工具次数和总时限约束的智能体循环，通过受控工具获取预测事实；构建
  BM25 + 向量召回 + 融合重排的医疗知识库并通过 MCP 接入，支持引用校验和渐进式 Skill。
- 完成容器化部署、链路追踪、指标监控和阶梯压测；本机 4 个工作线程的 ONNX + MySQL 业务链
  达到 `221.6 QPS`、`P99 24.5 ms`，64 虚拟用户过载后队列归零，压测后健康检查为 `0.96 ms`。

## C++ 后端岗位精简版

### treeSem 医疗智能服务｜C++ 后端 / 模型部署

**技术栈：** C++17、Muduo、ONNX Runtime、MySQL、Docker、Prometheus

- 基于 Kama/Muduo 二次开发 Reactor HTTP 服务，将推理、数据库和远程调用隔离到独立有界
  线程池，实现超时、背压、跨线程安全回包及优雅停机。
- 设计版本化模型服务包，在 C++ 中完成 ONNX 推理、特征预处理和决策树解释；1489 个样本
  Python/C++ 最大概率误差 `1.79×10⁻⁷`，支持主备切换与灰度一致性验证。
- 使用 MySQL 短事务和有界连接池持久化会话、预测与历史记录，支持幂等写入、连接获取超时、
  坏连接恢复和服务就绪检查。
- 本机 4 个工作线程的 ONNX + MySQL 业务链达到 `221.6 QPS`、`P99 24.5 ms`；64 虚拟用户过载时
  快速拒绝，负载结束后队列归零，压测后健康检查为 `0.96 ms`。

## Agent 岗位精简版

### treeSem 医疗智能 Agent｜工具调用 / RAG / MCP

**技术栈：** Python、C++、MCP、FAISS、MySQL、Docker

- 构建带步骤、工具次数、重复调用和总时限约束的智能体循环，通过受控领域工具获取预测、
  解释、历史与比较结果，避免大模型直接生成业务事实。
- 使用 BM25 与向量检索双路召回、融合排序和交叉编码器重排构建版本化医疗知识库，通过 MCP
  接入智能体；固定评测集 Recall@5 `0.9375`、MRR@10 `0.9271`，支持无答案与引用校验。
- 实现预测解释、历史比较和循证教育三个声明式 Skill，按角色渐进加载，并通过短期能力令牌
  绑定用户、会话、患者及可调用工具，阻断跨患者访问。
- 建立 60 条确定性智能体回归用例及跨服务链路追踪，覆盖工具选择、错误恢复、知识引用、
  提示注入和角色隔离；接入 `qwen-plus` 完成六个代表场景真实冒烟，任务和安全硬指标全部通过。

## 接入真实大模型后的替换项

完整 60 场景真实大模型评测完成后，再用下面的完整数据替换 Agent 版本最后一条，不额外增加一整段：

> 在【模型名称】上完成 60 条多轮场景评测，任务成功率【xx%】、工具参数有效率【xx%】、
> 引用有效率【100%】、端到端 P95【xx s】；覆盖工具超时、无答案、提示注入和跨角色访问。

其中只有实际测出的指标才能填写。真实模型数据用于说明智能体质量；`221.6 QPS / P99 24.5 ms`
用于说明 C++ + MySQL 业务链性能，两者不能混为同一套压测结果。

## 使用建议

- 投递综合后端或大模型应用岗位时使用“推荐主版本”。
- 投递纯 C++ 后端时使用 C++ 版，不必强行展开 RAG 和 Skill。
- 投递 Agent/RAG 岗位时使用 Agent 版，保留一条 C++ Gateway 和权限边界即可。
- 如果简历只能给项目留下 4 条，主版本优先删除 MySQL 或可观测性中与目标岗位较弱的一条，
  不要压缩成一条塞满十几个技术名词的长句。
